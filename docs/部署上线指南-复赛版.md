# 部署上线指南（复赛版）

> **目标**：让评审可直接打开链接体验完整产品，符合复赛"软件类作品必须部署上线"硬性要求。
> **方案**：多套部署方案，主备冗余，确保评审期持续可访问。
> **免备案**：全部使用海外托管（Render / Vercel / Hugging Face Spaces），无需 ICP 备案。

---

## 一、部署方案对比

| 方案 | 用途 | 优势 | 限制 |
|---|---|---|---|
| **主方案**：Render（后端）+ Vercel（前端） | 评审主入口 | 免备案 / 自动 HTTPS / CI/CD | Render Free 层 15 分钟休眠 |
| **备用方案 1**：Hugging Face Spaces | 后端冗余 | 16GB RAM 免费 / 不休眠 | 国内访问稍慢 |
| **备用方案 2**：本地 Docker Compose | 评审本地复刻 | 完整功能 / 数据可控 | 需评审本地安装 Docker |
| **应急方案**：Cloudflare Tunnel | 临时公网 | 无需服务器 | 需本地运行 |

## 二、主方案：Render（后端）+ Vercel（前端）

### 2.1 后端部署到 Render

#### 步骤 1：准备仓库

```bash
# 仓库已公开：https://github.com/Jim1160668677/ai-drug-platform
# 确认 render.yaml 已在仓库根目录
```

#### 步骤 2：创建 Render Blueprint

1. 登录 https://dashboard.render.com（用 GitHub 账号）
2. 点击 **New** → **Blueprint**
3. 选择仓库 `Jim1160668677/ai-drug-platform`
4. Render 自动识别 `render.yaml`，创建 `ai-drug-backend` 服务
5. 点击 **Apply** 开始构建

#### 步骤 3：配置环境变量

在 Render 控制台 → Environment 中确认/修改：

| Key | Value | 说明 |
|---|---|---|
| `USE_MOCK` | `true` | 默认 Mock 模式 |
| `CORS_ORIGINS` | `*` | 临时允许所有源 |
| `JWT_SECRET_KEY` | （Render 自动生成或手动设置强密钥） | 生产环境必改 |
| `AGNES_API_KEY` | （在 Render 控制台手动填入，sync: false 不显示日志） | 仅评审测试 Key |

#### 步骤 4：等待部署完成

- 首次构建：10-15 分钟（含 Docker 镜像构建 + 依赖安装）
- 健康检查：Render 自动访问 `/health`，返回 200 即部署成功
- 获取公网 URL：`https://ai-drug-backend.onrender.com`（实例名可能不同）

#### 步骤 5：验证

```bash
curl https://<your-render-url>/health
# 期望返回：{"status":"healthy","version":"2.0.0",...}

curl https://<your-render-url>/docs
# 期望返回：Swagger UI HTML
```

### 2.2 前端部署到 Vercel

#### 步骤 1：导入仓库

1. 登录 https://vercel.com（用 GitHub 账号）
2. 点击 **Add New** → **Project**
3. 选择仓库 `Jim1160668677/ai-drug-platform`
4. 配置：
   - **Root Directory**: `frontend`
   - **Framework Preset**: Next.js
   - **Build Command**: `npm run build`
   - **Output Directory**: `.next`（自动识别）

#### 步骤 2：配置环境变量

在 Vercel → Settings → Environment Variables 中添加：

| Key | Value |
|---|---|
| `NEXT_PUBLIC_API_BASE_URL` | `https://<your-render-url>/api/v1` |
| `NEXT_PUBLIC_USE_MOCK` | `false` |
| `NEXT_TELEMETRY_DISABLED` | `1` |

#### 步骤 3：部署

点击 **Deploy**，等待 2-3 分钟构建完成。
获取公网 URL：`https://ai-drug-platform.vercel.app`（项目名可能不同）

#### 步骤 4：更新后端 CORS

将 Render 后端的 `CORS_ORIGINS` 改为实际的 Vercel 域名：

```
CORS_ORIGINS=https://ai-drug-platform.vercel.app
```

重启 Render 服务生效。

#### 步骤 5：验证

打开前端 URL，应看到登录页。使用测试账号 `sid@ai-drug.com` / `demo123456` 登录，应进入工作台。

## 三、备用方案 1：Hugging Face Spaces

> 适用于 Render Free 层 OOM 或评审期持续访问场景。HF Spaces 提供 16GB RAM 免费层，不休眠。

### 3.1 部署步骤

1. 注册 https://huggingface.co 账号
2. 点击 **New Space**
   - Owner: 你的账号
   - Space name: `ai-drug-platform`
   - License: MIT
   - SDK: Docker
   - Visibility: Public
3. 上传文件：
   - 根目录 `Dockerfile`（已配置 HF Spaces 适配，端口 7860）
   - `backend/` 全部代码
4. 在 Space Settings → Repository secrets 中添加：
   - `AGNES_API_KEY` = 评审测试 Key
5. 等待构建完成（约 5-10 分钟）
6. 获取公网 URL：`https://<your-username>-ai-drug-platform.hf.space`

### 3.2 优势

- 16GB RAM（rdkit 加载无忧）
- 不休眠（持续可访问）
- 完全免费
- 自动 HTTPS

### 3.3 限制

- 国内访问稍慢（建议作为备用方案）
- 仅部署后端，前端仍需 Vercel

## 四、备用方案 2：本地 Docker Compose

> 适用于评审希望本地复刻的场景。

### 4.1 一键部署

```bash
git clone https://github.com/Jim1160668677/ai-drug-platform.git
cd ai-drug-platform
cp .env.example .env
docker compose -f docker-compose.prod.yml up -d
```

### 4.2 访问

| 服务 | URL |
|---|---|
| 前端 | http://localhost |
| API 文档 | http://localhost/docs |
| MinIO 控制台 | http://localhost:9001 |
| Neo4j | http://localhost:7474 |

### 4.3 初始化数据

```bash
docker compose -f docker-compose.prod.yml exec backend python -m app.db.seed
```

## 五、应急方案：Cloudflare Tunnel

> 适用于临时公网访问，无需服务器。

```bash
# 安装 cloudflared
winget install --id Cloudflare.cloudflared

# 启动本地后端
cd backend
uvicorn app.main:app --host 0.0.0.0 --port 8000

# 创建临时公网隧道
cloudflared tunnel --url http://localhost:8000
```

获取临时 URL（如 `https://random-words-xxx.trycloudflare.com`），即可被评审访问。

## 八、部署故障排查

### Q1: Render 部署失败，日志显示 OOM

A: rdkit 加载需要 300-400MB RAM，Free 层 512MB 可能不足。解决方案：
1. 升级到 Standard 层（2GB RAM，$7/月）
2. 或改用 Hugging Face Spaces（16GB RAM 免费）
3. 或本地 Docker Compose 部署

### Q2: Vercel 部署失败，构建错误

A: 检查：
1. Root Directory 是否设置为 `frontend`
2. Node.js 版本是否 18+（Vercel 默认 20.x）
3. `package-lock.json` 是否存在（用 `npm ci` 而非 `npm install`）

### Q3: 前端调用后端 API 报 CORS 错误

A: 在 Render 后端 `CORS_ORIGINS` 中添加 Vercel 域名：
```
CORS_ORIGINS=https://<your-vercel-domain>.vercel.app
```
重启 Render 服务生效。

### Q4: 部署后登录失败

A: 检查：
1. 后端是否已执行 `python -m app.db.seed` 灌入测试账号
2. JWT_SECRET_KEY 是否一致（前后端不共享，但后端签名必须稳定）
3. 数据库是否初始化（SQLite 模式下首次启动自动创建）

### Q5: Render Free 层 15 分钟后休眠

A: 解决方案：
1. 升级到 Standard 层（不休眠）
2. 或使用 Hugging Face Spaces（不休眠）
3. 或用 uptime-robot 等服务定时 ping `/health` 保持唤醒（不推荐，违反 Free 层 TOS）
